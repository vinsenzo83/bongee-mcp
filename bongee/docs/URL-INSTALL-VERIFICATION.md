# 주소 자동 설치 검증 · v0.3.1

2026-10-08 기준. 전체 자동 검사 **106개 통과, 실패 0개 및 후속 중복 자동 설치 검사 1개 통과**. OAuth 14개, 사용자 격리 8개, 연결 ZIP 5개, 자동 준비 3개, 소스 내부 링크 2개, 실행기 프로필 2개, 기존 HTTP 7개, OAuth 통합 6개와 기존 세션·자동 개발 검사를 포함합니다.

공개 Railway 서버에서 실제 MCP SDK로 주소만 입력해 인증 발견 → 자동 클라이언트 등록 → PKCE → 연결 허용 → 토큰 자동 발급 → MCP 초기화 → 425개 도구 목록을 확인했습니다. 비밀값을 수동으로 입력하지 않았습니다. 실제 Codex CLI에도 URL 방식으로 등록하고 자동 OAuth 인증을 완료했습니다.

새 사용자 세션에서 `bongee_auto_setup` → 세션 터미널 자동 실행 → 공개 소스 다운로드·SHA256 검증 → 의존성 설치 → 개인 실행기 시작 → 서버 연결 확인 → 실제 `system_status` 실행을 완료했습니다. 사용자 수동 ZIP 다운로드·토큰 입력·설치 명령 입력을 수행하지 않았습니다. 호스트 세션이 실행 명령을 처리하며 호스트의 명령 승인 정책은 유지됩니다. 현재 자동 준비 실행기의 소스는 검증된 v0.3.0 릴리스에 고정돼 있습니다.

원본 소스의 내부 심볼릭 링크 4개를 정상 보존하도록 설치기를 수정했습니다. 루트 밖으로 나가는 링크·다른 링크를 통과하는 링크·링크 밑 쓰기 경로는 거부합니다. 설치 중 반복 조회는 발급한 명령을 재사용하거나 준비 중으로 표시해 기존 실행기 연결 권한을 바꾸지 않습니다.

새 사용자 연결에서는 본인 실행기가 미연결로 표시되었습니다. 관리자 승인으로 기존 실행기에 연결한 본인 브라우저 세션에서는 실행기 연결·Codex/Claude CLI 로그인 상태와 실제 `system_status` 원본 도구 실행을 확인했습니다. 다른 사용자에게 기존 실행기 권한을 자동으로 제공하지 않습니다.

독립 검토에서 공개 설치 안내 방문이 사용자 공간 한도를 소모하는 문제를 발견해 수정했습니다. 새 브라우저 70회 방문 후 공간은 관리자 1개만 유지되고 신규 실행기 발급이 가능한 회귀 검사로 확인했습니다.

기존 설치 재사용은 설치 SHA256 표식과 실행기 파일을 확인합니다. 최초 다운로드의 공개 ZIP SHA256 검증과 로컬 설치된 모든 파일의 무결성 검사는 구분합니다.

검증 스크립트: `npm test`, `node check-oauth.mjs`, `node check-oauth.mjs --owner`. 출력과 근거에는 토큰·쿠키·인증 코드를 포함하지 않습니다. 424개 전체 도구의 기능별 완전 검증, Claude 구독 한도 해소, Windows 네이티브 실행 검증을 뜻하지 않습니다.
