# v0.4.2 실행기·연결 표시 검수

검수일: 2026-10-09. 로컬 후보 자동 테스트 151개 통과. 모의 테스트, 실제 모델 실행, 독립 계산 검사, 실제 배포 확인을 구분한다.

## 수정 사항

- Claude Code가 설치된 PC는 연결 설치 과정에서 하단 명령도 설정한다. 기존 명령과 최초 백업은 버전 경로 변경 후에도 보존한다.
- 최근 15초 이내 인증된 실행기 heartbeat와 살아 있는 소유 프로세스를 근거로 연결 상태를 표시한다. 원격 설치 프로필의 프로젝트 기록도 포함한다. 기록이 없으면 연결 확인 전으로 남긴다.
- 이 표시는 실행기 연결이다. 현재 채팅의 MCP 연결, 다른 AI 세션 연결, 작업 완료를 대신하지 않는다. Codex 앱·CLI 기본 하단에 임의 문구를 추가하지 않는다.
- 프로필·프로세스가 달라도 동일·상하위·심볼릭 링크로 겹치는 작업 폴더의 자동 파이프라인 동시 쓰기를 차단한다. 모든 실행기가 새 버전이어야 공통 잠금이 적용된다. 다른 프로그램의 수동 쓰기까지 막는 OS 잠금은 아니다.
- 재개 인수를 허용 목록으로 제한하고, 오류·중단 시 하위 작업 정리 확인 전에는 쓰기 권한을 해제하지 않는다. 예기치 않은 종료 후 잠금은 자동 만료되지 않으며 하위 작업 종료 확인 후 수동 복구가 필요하다.
- 검증 시작 단계를 실행 전에 저장하고 잠금 정리 실패를 기록한다. 파일 실행 권한 변경도 검증 근거 변경으로 감지한다.
- Claude의 구조화된 표준 출력에 있는 429 사용 한도 및 인증 오류를 비밀 원문 없이 실패 사유로 분류한다.

## 실제 모델 자동 개발

격리된 두 예제에서 실제 Codex CLI를 실행했다. Claude CLI는 인증 확인에 성공했으나 실제 요청은 주간 사용 한도 429로 실패했다. 명시적으로 공급자를 Codex로 바꾸어 재개했다. Claude 자동 개발 성공으로 계산하지 않는다.

| 예제 | 결과 |
|---|---|
| 정수 센트 금액·할인 계산 | 기획·조사·설계·디자인·개발·테스트·리뷰 7역할 및 등록 검사 완료 |
| 작업 상태 집계 | 기능 테스트 및 독립 500개 무작위 사례 통과. 최초 의도적 실패 테스트를 검증 전에 제거해 감사 절차 조건 불충족. 리뷰가 거부하고 수정 횟수 상한에서 실패 종료 |

금액 계산 결과물은 별도 BigInt 기준값과 정상 116,304건, 잘못된 입력 46건 비교에서 오류 0건이었다. 안전 정수 최댓값 인근, 0~100% 할인, 반올림, overflow, 타입 검사, 입력 불변성을 확인했다. 이는 해당 계산 모듈의 제한된 시험이며 임의 제품의 품질 보장이 아니다. 외부 acceptance 테스트와 산출물 해시는 독립 검증 전후 동일했다.

첫 예제의 감사 절차 미충족은 성공으로 변경하지 않았다. 자동 수정 반복이 모든 실패를 복구한다는 근거로 삼지 않는다.

## 세션 통신 부하

격리된 실제 Node 프로세스 10개에서 메시지 500개, 중복 재시도 50개를 처리했다. 고유 메시지 유실·중복 0건, 동시 조회 367회 일관성 확인, 보고 10개 완료. 4.206초 집중 부하에서 지연 p50 6.12ms / p95 259.86ms / p99 1065.86ms / 최대 2596.97ms였다.

기본 10초 heartbeat로 120초 관찰한 동안 각 프로세스의 상대 9개와 수신함을 유지했다. 2분 시험은 장기 안정성 보장이 아니다. 재시작된 endpoint는 새 ID를 가지므로 이전 ID 앞으로 온 메시지는 새 수신함에 자동 이관되지 않는다. 기존 보고는 보존된다.

## 남은 범위

- 실제 Claude 실행과 Codex·Claude 양방향 장시간 협업은 사용 한도 해소 후 검증 필요.
- 실제 다른 사람의 BATON 단체방 메시지·권한 흐름은 이번 검수에서 실행하지 않음.
- 모든 431개 도구 개별 동작, 장기간 운영, 임의 프로젝트 자동 개발 품질을 보증하지 않음.
- Claude Code 실제 화면 렌더링은 클라이언트 설정·정책·세션 갱신에 영향을 받는다. 명령 출력 검증과 실제 앱 하단 관찰을 구분한다.
- 빌드가 검사 대상 파일을 바꾸는 프로젝트는 검증 중 변경으로 판정될 수 있으므로 검사 명령·출력 위치를 맞춰야 한다.

원본 증거는 로컬 `output/bongee-mcp/full-audit`에 보관한다. 개인 경로·인증·작업 원문은 공개 패키지에 포함하지 않는다.
