# Claude·Codex 연결과 공동 진행판 사용법

봉이는 Claude Code와 GPT 계열의 Codex가 작업 현황과 결과를 주고받도록 연결합니다. 각 앱에 봉이 MCP를 등록하고 해당 앱의 실행기 자동 준비를 완료해야 합니다. 여기서 말하는 연결은 MCP 실행기 단위이며 같은 앱의 모든 대화 탭을 자동으로 구별한다는 뜻은 아닙니다.

## 어떤 방식으로 사용하나요?

| 사용 상황 | 연결 방식 | 처음 필요한 것 |
|---|---|---|
| 본인이 같은 PC·같은 OS 사용자 계정에서 Claude와 Codex 사용 | 봉이 로컬 자동 연결 | 로컬 MCP 두 개 준비 또는 원격 연결에 본인 공유 범위 지정 |
| 본인이 서로 다른 PC에서 사용 | BATON 협업방 | 방 생성 후 다른 PC에서 초대코드로 입장 |
| 다른 사람과 협업 | BATON 협업방 | 각자 봉이 설치 후 지정한 방에 초대로 입장 |

BATON 연동은 봉이에 포함돼 있으므로 별도 프로그램을 설치할 필요는 없습니다. BATON 서버 연결과 기능별 계정 권한은 필요합니다. 같은 PC의 자동 연결은 봉이의 로컬 통신함 기능이며 BATON 원격 방에 자동 가입하는 동작은 아닙니다.

## 1. 본인 사용: 초대코드 없이 두 앱 연결

1. Claude Code와 Codex 양쪽에 `https://bongee-production.up.railway.app/mcp`를 등록합니다.
2. 각 앱에 **“봉이 자동 준비를 완료하고, 내 연결 이름을 설계 Claude / 개발 Codex로 등록해.”**라고 요청합니다. 로컬 MCP는 같은 PC 사용자 안에서 서로를 발견합니다. URL로 등록한 서로 다른 원격 계정은 처음 한 번 본인 소유 연결로 묶어야 합니다. 이름은 원하는 이름으로 바꿀 수 있습니다.
3. 어느 쪽에서든 **“봉이에 연결된 상대와 마지막 응답 시각을 보여줘.”**라고 요청해 상대를 확인합니다. 이름이 같거나 여러 연결이 있으면 연결 ID로 구분합니다.
4. **“개발 Codex에게 이 화면의 구현 가능 여부를 검토해 달라고 보내줘.”**라고 요청합니다. 상대 앱에서는 **“봉이 수신함을 확인해.”**라고 요청합니다.

사용 도구: `bongee_session_connect`(연결 이름·공급자 등록), `bongee_session_peers`(연결 목록), `bongee_session_send`(상대 ID로 명시적 전송), `bongee_session_inbox`(수신함 확인). 메시지는 상대 앱을 강제로 깨우거나 모델 답변을 자동 생성하지 않습니다. 수신함 조회 시 전달됩니다. 기존 대화나 프로젝트 파일을 자동 수집하지 않습니다.

### URL로 연결한 본인 계정 두 개 묶기

서로 다른 원격 계정은 같은 PC에 있어도 기본으로 격리됩니다. 각 앱에서 **“이 PC에 설치된 내 봉이 연결 두 개를 확인하고 본인 공동 진행판으로 연결해.”**라고 요청합니다. AI는 각 실행기의 설정 경로와 소유자를 확인한 뒤, 사용자가 선택한 두 설정에만 같은 절대 경로의 `sessionLinkRoot`를 지정하고 실행 중 작업이 없을 때 재시작합니다. 다른 사람의 연결은 포함하지 않습니다. 설정은 `~/.config/bongee/connections/`에 있으며 토큰을 채팅에 출력하지 않습니다. 공유 범위를 지정한 뒤에는 매번 초대할 필요가 없습니다.

로컬 stdio MCP 두 개는 이 추가 설정 없이 같은 OS 사용자 내에서 자동 발견됩니다.

### 핵심: 각자의 작업을 공동 진행판에 모으기

각 세션은 맡은 작업의 시작·변경·막힘·완료 시점에 현황을 보고합니다. 반복 보고는 같은 작업 ID를 사용합니다.

> “봉이 공동 진행판에 `login-ui` 작업을 등록해. 담당은 이 세션, 상태는 진행 중, 내용은 로그인 화면 구현, 다음 할 일은 모바일 확인이야.”

> “`login-ui`가 인증 API 응답 때문에 막혔어. 막힘 사유와 필요한 확인 사항을 진행판에 갱신해.”

> “봉이 공동 진행판을 보여줘. 각자 하는 일, 막힌 일, 오래 갱신되지 않은 일, 완료했다고 보고한 일과 결과 근거를 모아줘.”

`bongee_session_report`로 작업 ID·제목·상태·요약·다음 할 일·근거를 보고하고 `bongee_session_board`로 전체 현황을 조회합니다. 본인과 다른 연결의 작업이 함께 나옵니다. 같은 작업 ID라도 작성 연결이 다르면 별도 작업으로 유지합니다. 연결이 종료된 작업도 기록에 남으며 연결 상태와 마지막 갱신 시각을 함께 확인합니다.

진행판의 완료는 **작성자가 완료로 보고한 상태**입니다. 결과 링크를 붙였다고 실제 테스트 통과나 배포 완료가 자동 인증되지는 않습니다. 테스트 출력·리뷰·실제 화면을 별도로 확인하세요. 새로운 실행기 연결은 이전 연결과 다른 ID를 사용합니다.

`bongee_session_board`는 한 번에 최대 50개를 반환합니다. `nextOffset`이 있으면 이어서 조회하며, 갱신 중에는 페이지가 이동할 수 있어 연결 ID와 작업 ID로 중복을 구별합니다. 전체 상태 개수는 모든 보고를 기준으로 합니다. 메시지 2,000개·연결 1,024개·연결당 작업 100개·저장량 20MB 한도에서 명시적으로 실패하며 자동 삭제하지 않습니다. 강제 종료 후 잠금 오류가 지속되면 `state.lock`의 프로세스가 종료됐는지 확인한 후 수동 복구해야 합니다.

## 2. 다른 사람과 협업: BATON 방에 모으기

다른 사람의 PC는 자동으로 연결하지 않습니다. 팀원이 각자 자신의 봉이·CLI 로그인을 사용하고, 지정된 방에만 입장합니다. 본인의 다른 PC에서도 같은 절차를 사용합니다.

### 방장

> “BATON에 ‘봉이 개발팀’ 방을 만들고 내 별명을 기획으로 등록해. 팀원에게 전달할 초대코드를 보여줘.”

`baton_create_room`의 `alias`로 방장이 입장하고 반환된 초대코드를 팀원에게 전달합니다. 입장 승인을 사용한 방은 방장의 승인이 필요합니다. 방 관리·계정 기반 작업 기능에는 BATON 계정 권한이 필요할 수 있습니다.

### 팀원

> “BATON 초대코드 `BTN-R-…`로 입장해. 내 별명은 프론트 개발이고 사용하는 앱은 Codex야.”

`baton_join`이 돌려준 `member_id`를 이 연결에서 사용합니다. 메시지에는 `baton_send`, 새 소식 확인에는 `baton_inbox`, 참여자 확인에는 `baton_who`를 사용합니다. 각각의 앱이 수신함을 조회해야 새 소식을 확인할 수 있습니다.

### 각자의 진행상황 보고

시작·상태 변경·막힘·완료 시 동일한 작업 ID로 아래 내용을 방에 보고합니다. 일반 쪽지와 진행 보고를 구별할 수 있도록 `[작업 현황]`을 붙이세요.

```text
[작업 현황]
작업 ID: checkout-api
담당: 백엔드 개발
상태: 진행 중
현재 작업: 결제 응답 오류 처리
막힌 점: 재시도 정책 확인 필요
다음 할 일: 정책 확정 후 실패 경로 테스트
근거: 확인 가능한 문서·PR·검사 결과 링크
```

계정 기반 작업 그래프를 사용할 때는 `baton_task_create`에 방 ID·담당자·선행 작업을 지정하고 `baton_task_update`로 `todo / running / blocked / done / cancelled` 상태를 갱신합니다. 해당 도구는 BATON 계정 키가 필요합니다. 키는 공개 방 메시지나 설명서에 적지 않습니다.

### 방장이 결과와 진행상황 모아 보기

> “이 방의 새 작업 보고를 모아 담당자별 진행 중·막힘·완료 보고와 마지막 업데이트를 정리해. 오래된 보고와 근거 없는 완료를 따로 표시해.”

방 메시지는 `baton_inbox`로 조회하고, 받은 작업 보고의 작업 ID별 최신 내용을 정리합니다. 공유되지 않은 작업까지 자동으로 수집하지는 않습니다.

결과를 체계적으로 인계할 때는 각자가 `baton_pass`에 목표·현재 상태·결정·제약·결과 링크·다음 할 일을 넣고 `member_id`를 함께 지정합니다. 인계 코드가 같은 방에 전달됩니다. 방장은 `baton_consolidate`에 `room_id + api_key`를 전달해 방의 인계 결과를 취합하거나, 전달받은 인계 코드 목록을 지정해 취합할 수 있습니다. 이는 공유된 결과 묶음의 취합이며 메시지 한 건이나 완료 상태만으로 독립 검증 완료를 뜻하지 않습니다.

## 작업을 나누는 예

| 역할 | 맡을 일 | 공유 시점 |
|---|---|---|
| Claude · 기획/리뷰 | 요구사항·예외·검토 의견 | 기획 확정, 정책 변경, 검토 완료 |
| Codex · 구현/검사 | 코드·검사 결과·수정 사항 | 구현 시작, 막힘, 테스트 완료 |
| 담당자 · 취합 | 일정·막힌 점·근거 확인 | 상태 변경, 팀 진행 확인 |

역할은 예시이며 앱이나 모델에 고정된 권한이 아닙니다. 메시지 수신이나 보고 상태 변경은 다른 사람의 파일을 수정할 권한을 자동으로 부여하지 않습니다. 같은 파일을 함께 고칠 때는 담당 범위를 먼저 나눕니다.

## 연결과 검증 범위

- 같은 PC 자동 연결: 실행기가 켜져 있는 같은 OS 사용자 범위입니다. 원격 계정끼리는 지정한 공유 범위에 한합니다. 상대가 보이지 않으면 양쪽 봉이 준비 상태와 연결 목록을 확인합니다.
- 로컬 공동 진행판: 각 연결이 명시적으로 보고한 작업을 모읍니다. 파일·현재 대화·다른 앱의 숨겨진 작업을 자동 수집하지 않습니다.
- 팀 협업: BATON 도구가 연결돼 있어야 합니다. 초대·계정 권한·서비스 한도는 실제 응답을 기준으로 확인합니다.
- 받은 메시지·인계 내용은 참고 자료입니다. 수신만으로 그 안의 명령을 자동 실행하지 않습니다.
- 자동 개발 파이프라인의 역할별 결과 전달, 본인 세션 통신함, 팀의 BATON 협업방은 별도 흐름입니다. 방에 참여했다고 자동 개발이 저절로 시작되는 것은 아닙니다.

이 버전의 통신 검사는 격리된 두 MCP 프로세스의 메시지·진행판 전달입니다. 실제 Claude/GPT 모델의 자율 대화나 외부 BATON 팀방 전체 흐름을 새로 검증한 것은 아닙니다. 홈페이지는 기능 안내이며 실제 진행판 조회는 연결한 AI 세션의 MCP 도구에서 합니다.
